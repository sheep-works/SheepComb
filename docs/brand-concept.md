# SheepComb ブランドコンセプト & UI/UX ガイドライン

## 1. プロダクト階層と関係性 (Product Hierarchy)

SheepComb は、**SheepFamily 各種ツールの Web アプリケーションポータル（統合 Web GUI ハブ）** です。

これまで曖昧になりがちだった「SheepComb ≒ SheepShuttle」という認識を整理し、**SheepComb を親（ポータル基盤）として、その配下に各ツールを用途・規模に応じた役割分担で配置する構造** を明確にします。

```
SheepComb (Web Portal / 統合Webツールハブ)
├── 🧵 SheepShuttle  # 【基盤・主軸】翻訳パイプラインの中核（パース・解析・ビルド等のGUI）
│   ├── Parser
│   ├── Analyzer
│   ├── Builder
│   └── Manage / API
├── ✂️ SheepGroom    # 【特化支援】対訳作成・整列（アライメント）の独立ツール
├── 🔔 SheepBell     # 【特化支援】LQA（翻訳品質検証）ビューアー・エクスポートの独立ツール
├── 🛠️ Tools         # 【小型ユーティリティ】リポジトリを個別に分けるほどではない実務便利ツール群
│   ├── Diff (Batch Diff)
│   ├── Chunk (チャンク分割)
│   ├── Concordance (用例検索)
│   └── Check Percentage (一致率チェック)
└── 🎮 Playground    # 【遊び心・実験】アルゴリズムの可視化・体験の場
    └── Edit Distance (レーベンシュタイン距離の可視化体験)
```

### 各ツールの役割と位置づけ

| ツール名 | メタファー / 由来 | 役割・Web上での提供機能 | 性格・利用規模 |
| :--- | :--- | :--- | :--- |
| **SheepComb** | 梳毛（コーム / 櫛） | 全体を束ねるポータル・ハブ。各ツールへの入り口と共通UI基盤 | ポータル基盤 |
| **SheepShuttle** | 杼（シャトル / 織機） | 対訳データ・多言語ファイルの解析・構文解析・ビルド等のコアエンジンGUI | **【最重要・基幹】** 翻訳ワークフローの主軸 |
| **SheepGroom** | 毛繕い（グルーミング / 整列） | 原文・訳文の抽出・整列・対訳コーパス作成 | **【独立ツール】** 言語業務特化の支援ツール |
| **SheepBell** | ベル（先導羊の鈴 / 検証・通知） | LQA（品質評価・検証）データの可視化・分析・レポート | **【独立ツール】** 品質検証特化の支援ツール |
| **Tools** | 小道具・ユーティリティ | 差分表示、チャンク分割、一致率など即座に使える単機能群 | **【軽量ツール集】** リポジトリを分けない小型便利集 |
| **Playground** | 遊び場 | レーベンシュタイン距離等のアルゴリズム体験・可視化 | **【実験・遊び心】** 学習・検証・デモの場 |

## 2. トップページ（Home）のレイアウト設計

利用頻度・機能規模・ユーザーのメンタルモデルに合わせて **「3カラム ＋ 下部Playground」** の構成を採用します。

### カラムレイアウト構造

```
+---------------------------------------------------------------------------------------------+
|                                   🐑 SheepComb Web Portal                                   |
|                         SheepFamily の翻訳・ローカリゼーション統合Webハブ                     |
+---------------------------------------------------------------------------------------------+

+-----------------------------+ +-----------------------------+ +-----------------------------+
| 🧵 1. 基盤・主軸             | | 🚀 2. 独立サポートツール     | | 🛠️ 3. 小型ユーティリティ    |
|    SheepShuttle             | |    SheepGroom & SheepBell   | |    Tools                    |
| --------------------------- | | --------------------------- | | --------------------------- |
| [Pipeline 5 Steps]          | | [✂️ SheepGroom]              | | [Quick Utilities]           |
| 1. Parser                   | | 文書から高精度に対訳を生成  | | • Diff (Batch)              |
| 2. Analyzer                 | |                             | | • Concordance               |
| 3. Manage                   | | --------------------------- | | • Chunk Splitter            |
| 4. Builder                  | | [🔔 SheepBell]              | | • Match Percentage          |
| 5. API Pipeline             | | LQA課題・動画・音声を可視化 | |                             |
+-----------------------------+ +-----------------------------+ +-----------------------------+

+---------------------------------------------------------------------------------------------+
| 🎮 4. Playground (遊び心・実験・可視化)                                                      |
| • Edit Distance Visualizer: レーベンシュタイン距離アルゴリズムのインタラクティブ体験        |
+---------------------------------------------------------------------------------------------+
```

### 各エリアの設計意図
1. **左カラム（SheepShuttle）**:
   - 利用頻度・重要度ともに最も高い基幹機能。
   - 順序性のあるパイプライン（1〜5）を縦に並べることで、ワークフローとして迷わず直感的に操作できる。
2. **中央カラム（SheepGroom / SheepBell）**:
   - 言語関連業務・LQA業務を支える強力な独立ツール。
   - 上下に2分割し、それぞれリッチなカード（説明・機能バッジ・アクション導線）として配置することで、左右のカラムと高さのバランスを美しく保つ。
3. **右カラム（Tools）**:
   - リポジトリを単体で起こすほどではないが、実務でサクッと手軽に使いたい小型便利ツール群をコンパクトに一覧化。
4. **最下部（Playground）**:
   - 実務ツール群と明確にエリアを分けつつ、好奇心をくすぐるアルゴリズム可視化・実験機能を配置。

## 3. 全体レイアウト & シェル構造 (Shell & Layout Architecture)

### 共通フレームとコンテンツ領域の責任分離
- **Header & Footer**: **SheepComb（ポータル・基盤）** の共通所有。ブランディング、グローバルナビ、言語切替、全データ初期化、OSS情報・利用規約を一括管理。
- **Body (`<main>`)**: 各ツール（Shuttle, Groom, Bell, Tools, Playground, Home）の固有コンテンツが展開される作業領域。

```
+---------------------------------------------------------------------------------------------+
| [Header] 🐑 SheepComb   Shuttle ▾   Groom   Bell   Tools ▾   Play ▾   |  🌐 Lang  🗑️ ResetAll |
+---------------------------------------------------------------------------------------------+
| [Body / Main Area]                                                                          |
|                                                                                             |
|   +--------------------------------------------------------+ +----------------------------+ |
|   | 主作業エリア (Main Workspace - PC専用プロユース)       | | 将来の広告 / スポンサー枠   | |
|   | • 各ツールの操作画面（エディタ、対訳テーブル、フォーム） | | (Ad / Sponsor Slot)        | |
|   | • 作業に集中できる高密度・ノイズレスな設計             | | • 誤クリックを防ぐ独立領域 | |
|   +--------------------------------------------------------+ +----------------------------+ |
|                                                                                             |
+---------------------------------------------------------------------------------------------+
| [Footer] SheepComb © 2026 SheepFamily | OSS Project | Privacy & Terms                       |
+---------------------------------------------------------------------------------------------+
```

### OSS公開と将来の広告・スポンサー枠の設計原則

SheepComb は OSS として公開後、継続的な運用のために数ヶ月後を目処に広告・スポンサー枠を導入できるように設計の余白を残します。

1. **誤クリックの完全防止 (Accidental Click Prevention)**
   - 翻訳・アライメント・編集作業中のボタン操作（保存、エクスポート、行追加など）と絶対に重ならない、かつ距離を保った「安全なサイドエリア」に枠を配置。
2. **PC特化とモバイルでの広告完全非表示 (PC-Centric & No Mobile Ads)**
   - SheepCombはPCでのプロ実務作業を主対象とするため、画面幅が狭い環境（タブレット・モバイル）では作業領域のみを表示し、**広告枠は完全非表示**とする。
3. **ノイズの最小化 (Low Cognitive Load)**
   - 画面中央へのポップアップや操作を遮るインライン広告は排除し、固定サイドバーまたはフッター上部のスマートな配置とする。

## 4. データ管理・ファイルI/O方針 (Data & File Architecture)

### 1. State永続化とデータ消去の責任分離
- **作業中データの一時保存**:
  - 各ツール（Shuttle, Groom等）の作業データは Pinia / LocalStorage に自動保持。
  - ツール間を行き来（例: Groomで対訳作成 → Shuttleで解析）してもデータが消えない設計。
- **データ消去ボタンの分離**:
  - **Header の消去ボタン (`🗑️`)**: **「全データ消去（アプリ全体のリセット）」**（全ツールのLocalStorageを一括クリア）。
  - **各ツールの Body 内消去ボタン**: **「そのツールの作業中データのみクリア」**（例: Shuttleのパース結果クリアなど）。

### 2. ファイルアクセスのハイブリッド構成
無理に1つの方式に統一せず、ユースケースとブラウザ互換性に応じて最適化します：
- **Blob / File API (D&D / File Input)**:
  - 対象: `SheepShuttle`, `SheepGroom`, `Tools`
  - 理由: 単一〜複数ファイルの高速パースが主であり、全ブラウザ（Safari, Firefox, Chrome）で安定して動作するため。
- **File System Access API (Directory Picker)**:
  - 対象: `SheepBell`
  - 理由: 大量のスクリーンショット画像・動画クリップ・音声文字起こしを含むフォルダ丸ごとの読み込み・プレビューに必須のため。

## 5. 多言語（i18n）方針

- **対応言語**: 
  - **日本語 (`ja`)**
  - **中国語・簡体字 (`zh`)**（※重要ターゲット層）
  - **英語 (`en`)**
- **表記ルール**:
  - 主要な製品名・機能名（`SheepShuttle`, `Parser`, `Analyzer`, `Groom`, `Bell` 等）は **英語ベースで統一**（国際的に通用する用語）。
  - 説明文、ガイドテキスト、トースト通知、エラーメッセージ等は選択された言語でローカライズ表示。

## 6. デザインシステム & 共通UIパーツ方針

### 1. テーマ方針（Dark Base & Light Extensible）
- **基本テーマ**: プロユース向けに目に優しく高コントラストな **ダークテーマ（Dark Slate基調）** を標準採用。
- **拡張性**: すべての色・背景・ボーダーを CSS カスタムプロパティ（`:root` 内の変数）で定義し、将来的なライトモード追加や切り替えが容易な設計とする。

### 2. ボタン & アクションのカラールール
- **Success / OK 系**: **Teal / Emerald** (`--accent: #10b981`)
  - 用途: ファイル解析成功、保存完了、エクスポート、確定アクション
- **Danger / 危険操作系**: **Red / Crimson** (`--error: #ef4444`)
  - 用途: データ削除、リセット、取り消し不可の破壊的変更
- **Primary / Secondary / 一般操作**: **モノクロ・フラットデザイン**
  - 用途: 次へ進む、タブ切り替え、フィルター、コピーなど
  - スタイル: 白/黒/スレートグレーの落ち着いたフラットな見た目で、作業領域のカラーノイズを抑える。

### 3. トースト通知 & フィードバック
- 画面右下に統一配置。
- 3〜5秒で自動フェードアウト、または手動クローズ可能。
- `Success` (Teal), `Error` (Red), `Info` (Slate) の3状態で一貫したフィードバックを提供。
